# Границы автоматизации

## Интерфейс против API

Не предполагать, что любой объект, видимый в веб-интерфейсе, доступен через API. Перед автоматизацией товара, фида, черновика или кампании:

1. Проверить присутствие через соответствующий `get` на подходящем endpoint.
2. Проверить возможность чтения статистики и записи на конкретном типе.
3. Если объект не возвращается, назвать его UI-only для данного аккаунта и не симулировать работу через API.
4. Не смешивать UI-only кампании с API-видимыми в отчётах без отдельной Метрики и маркировки ограничения.

## Фиды и листинги

Не считать наличие YML гарантией каталожных листингов. Перед запуском товарного размещения отдельно проверить доступные предложения, каталог/листинги, состояние фида и связь с кампанией в интерфейсе либо официальном API.

## Методологические стоп-сигналы

- Не отключать ключ, автотаргетинг или категорию только по CTR/CPC, если нет достоверной выручки или продаж.
- Не добавлять минус-фразы только по отсутствующей на сайте странице: сначала проверить реальный ассортимент, фид и ecommerce.
- Любое расхождение итогов между Direct и Метрикой — повод остановиться и воспроизвести подсчёт, а не подбирать красивое объяснение.
