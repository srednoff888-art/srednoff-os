# Контракт API Директа

Проверять конкретные поля по официальной документации версии API перед записью. В актуальной документации ЕПК работает на `v501`, а JSON-адрес имеет обязательный сегмент `/json/`.

## Аутентификация и ID

- Direct: `Authorization: Bearer <oauth-token>`, `Content-Type: application/json; charset=utf-8`; `Client-Login` передавать только при необходимости и не логировать.
- Все ID длиной 16+ цифр считать строками. При формировании JSON для API сохранять их как точные десятичные токены, а не как JavaScript number.
- Денежные поля в операциях — микроединицы; не менять бюджет/стратегию одновременно с несвязанными правками без явного согласования.

## ЕПК

- Кампания: `Campaign.Type=UNIFIED_CAMPAIGN`, структуры чтения и записи `UnifiedCampaign`.
- Группа: `UnifiedAdGroup` с явно заданным `OfferRetargeting`.
- Объявление: выбирать структуру по `Ad.Type`. Для `RESPONSIVE_AD` читать `ResponsiveAdFieldNames` и писать `ResponsiveAd`.
- Проверять типы объявлений и групп до создания: допустимые дочерние типы зависят от `AdGroup.Type`.

## Поля с асимметрией

- Уточнения могут читаться как объекты `AdExtensions`, а для создания/первичной привязки ожидаться как ID. Для обновления набора использовать текущую схему `CalloutSetting.AdExtensions` с операциями `SET`, `ADD` или `REMOVE`, если она предписана документацией данного типа объявления.
- Автотаргетинг читать и записывать в точном формате метода `Keywords`. После создания/изменения обязательно проверить категории через `Keywords.get`.
- Поля с `null` и формат обнуления проверять на тестовой или согласованной операции: сериализаторы PowerShell нередко меняют намеренное `null`.

## Отчёты

Использовать заголовки:

```text
processingMode: auto
returnMoneyInMicros: false
skipReportHeader: true
skipColumnHeader: false
skipReportSummary: true
```

HTTP 201/202 означает подготовку отчёта. Повторять тот же запрос с паузой, фиксировать RequestId и остановиться после ограниченного числа попыток. TSV может содержать запятую как десятичный разделитель; конвертировать осознанно.

## Локальный минимум верификации

1. `get` до записи: поля, затрагиваемые операцией.
2. Запись одного согласованного батча.
3. Проверить `Errors`, `Warnings`, RequestId и число результатов.
4. `get` после записи: точное значение целевых полей, состояние и статус модерации.
5. При несовпадении остановиться, не объяснять расхождение предположениями.
