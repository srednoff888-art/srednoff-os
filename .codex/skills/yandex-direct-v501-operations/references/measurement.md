# Метрика, UTM и Wordstat

## Метрика

- Reporting и Management API используют `Authorization: OAuth <token>`.
- Для управления обычно нужен `Content-Type: application/x-yametrika+json`; права доступа и scope подтверждать ответом API.
- Не строить сегмент «наши кампании» через `UTMCampaign != 'чужая'`: пустой UTM может попасть в выборку. Явно перечислять разрешённые значения `UTMCampaign` либо анализировать одну кампанию за запрос.
- Не соединять OR-фильтр по UTM с параметром attribution без отдельного контрольного запроса: сравнить результаты с раздельными запросами.

## Минимальный отчёт

Собирать как минимум: визиты, отказы, глубину, длительность, цели, ecommerce-покупки/выручку, `startURLPath`, UTM campaign/content/term и нативные поля кампании Директа. Проверять `sampled` и `sample_share`.

Контроль: визиты рекламного трафика должны быть сопоставимы с кликами Директа. Использовать 85–95% только как ориентир диагностики; объяснять различие данными, а не предположением о потере UTM.

## Wordstat

Wordstat в Yandex Cloud использует отдельный API key и folder ID. Не включать его без явного разрешения пользователя, если такое правило действует для проекта. Хранить ключ только в локальной конфигурации.

Оценивать частотность как входной сигнал. Добавлять 2–3 фразы, затем сверять `SEARCH_QUERY_PERFORMANCE_REPORT`, затраты и, при наличии, продажи/выручку. Не выводить ценность ключа только по частотности или CTR.
