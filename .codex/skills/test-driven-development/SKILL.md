# Test Driven Development

## Decisions

- Start with an observable failure or requirement and a test that discriminates correct behavior.
- Keep tests independent of implementation structure; use the existing test framework and smallest useful scope.

## Acceptance

Demonstrate red/green and run neighboring regressions after the change.

## Constraints

- Do not add brittle tests that only assert implementation details.
